# M6.1：WRITE RNDV 接收端 Grant 账本

[`GrantManager`](../kbsocket/connection/grant_manager.hpp) 在已有注册 Slab 上管理每连接的目标授权。它负责有界准入、完整身份、防重复授权，以及远端访问和本地应用持有两类责任。数据路径由唯一 owner 串行推进，不分配内存或注册 MR。

本阶段提供可独立验证的接收端原语。后续 M6.2–M6.3.5 已增加分块 WRITE、远端段导入、wire codec、通知提交和 [接收协调器](rndv-receiver.md)；Connection/Runtime 的自动 RNDV 装配仍未交付。

## 身份与有界准入

每个管理器一次绑定发送/接收 runtime、receive domain、session、完整连接 token、Arena 身份及代次、目标 Slab 和本地注册 context。宿主必须保证同一连接与 Arena incarnation 的组合不被替代管理器复用；单个对象禁止重新 Open，不能代替跨对象的身份分配策略。

每个请求携带 transfer ID、流序号 SN 和准确长度。返回的 Grant 还包括槽位、单调不回绕的授权代次及实际目标地址；匹配 DONE/终结证明时比较全部字段，不能只比较 transfer ID 或短连接 token。返回的 SGE 来自目标 context 的真实 Slab 注册，只描述已准入的连续区间。它是本地描述符，不能直接把含指针的结构复制成 wire 格式。

RTS 可以乱序。管理器在固定 SN 窗口内独立准入，不按请求到达顺序更新 transfer ID 高水位。同一 SN 一经准入，即使授权已经取消或归还，也保留已处理记录；窗口推进前，同一 SN 的重复请求或换 transfer ID/长度的请求均被拒绝。transfer ID 是完整身份的一部分，不单独充当全局去重键。

`AdvanceWindow` 只能单调推进，并先检查整个待退休前缀。只要其中还有预留、已发布、待交付、应用持有或隔离责任，就拒绝推进且不清除任何记录。序号使用 32 位流空间，边界使用 64 位计算，`UINT32_MAX` 留给 FIN，数据序号耗尽后不得回绕。宿主将来应以统一接收重排账本的实际释放前缀驱动此接口；当前窗口没有为 Eager/RNDV 共用序号创建占位，也不表示数据已经有序可读。

准入同时受固定窗口、活跃 Grant 数、活跃字节数及共享 Slab 的缓冲区/责任表容量约束。目标必须能放入一个 Slab 槽；整个 backing 由 Slab 的共享 MemoryBudget 计费。管理器的字节额度计量实际授权长度，不代替 backing 的物理内存预算。需要更大消息时，宿主在控制路径配置适合的 Arena，不能在准入失败时临时扩容。

## 发布与取消

正常流程为：

1. `Reserve` 取得 CPU Lease、独立 RemoteGrant 责任及目标 SGE，保持未发布状态。
2. 在描述符可能暴露给远端之前调用 `CommitPublication`，提交远端访问责任。
3. 发布 GRANT 并由后续发送端引擎执行 WRITE；本管理器不负责发送。
4. 经过可信 DONE 验证后解除远端访问责任，缓冲区进入待交付状态。
5. `Borrow` 返回只读视图，应用结束访问后 `Return` 归还 CPU 责任。

在第 2 步之前，`Cancel` 可以安全撤销预留并释放目标。第 2 步之后，取消只能隔离目标，继续保留 Grant、CPU Lease 和准入额度。发布结果未知也走这一分支，不能猜测远端未收到描述符。此接口保守地在可能发布之前提交责任；即使随后确认发送失败，也须通过可信终结入口解除已提交的授权。

应用借用不增加引用，不允许重复借用；管理器保持真实 CPU Lease 的所有权，调用方不能绕过 `Return` 直接释放 Slab。待交付和已借用的数据仍占活跃额度。已借出的视图不能被取消或关闭抢回；只有应用明确归还后才可复用。

## 成功交付与终结证明

`GrantTerminalEvidence` 是宿主的可信调用边界，不是可直接采信的网络报文字段。调用方必须先核验实际来源与会话，利用发送端逐 WR 账本证明：

- 不再有针对该 Grant 的排队、在途或未来新提交，包括重试路径；
- 接受集合已知，全部已接受 WRITE 都获得可信终结；
- 成功 DONE 还要求整个授权区间由互不重叠的分块完整覆盖，所有分块成功，准确字节数一致。

接口检查完整身份、禁止未来提交的声明、接受是否已知、接受/终结/成功计数及完成字节数。计数相等本身不能证明覆盖关系，完整区间校验仍是后续发送端事务账本的职责。一个本地 SEND 完成、最后一个 WRITE CQE、超时、控制 EOF、flush、Lane 替换或接收 JFR 删除，都不能独立构成这个证明。

`CompleteDone` 只在成功证明成立且授权仍允许交付时进入待交付状态。`ConfirmTerminal` 只作安全丢弃，绝不交付数据；它允许全部已接受访问终结但存在失败的情形。已经取消并隔离的授权，即使晚到完整成功 DONE，也只清理责任，不能重新变为可读。旧代次、错误范围、重复证明均不能解除新授权。

M6.3.5 的接收协调器经独占绑定和明确的对端成功通知契约，在校验实际来源、已发布 Grant 与完整线身份后调用私有无计数入口；不从 DONE 中虚构 accepted/terminal 数量。借用以真实 GrantHandle 进入共同窗口，应用归还仍由管理器执行。独占绑定期间 Close 拒绝关闭依赖；通知发布者的迟到取消只处理未完成发布，不丢弃已完成或已借出目标。

接收端 Grant 与发送端源 Lease 的本地 DMA 账本独立：源 WRITE 获得本地终结只解除相应源责任。目标端仍等待上述完整远端证明；目标端解除 Grant 后，应用 CPU 引用又继续阻止目标复用。

## 停止、关闭与依赖

`Stop` 停止本管理器的新准入，既有授权仍可完成或显式取消；它不停止共享 Slab，也不影响健康连接的准入。它不是连接失败通知；后续连接失败路径需要逐授权调用 `Cancel`。`Close` 先停准入，任何活跃责任存在时返回忙；不会根据连接状态合成 `EndGrant`，也不会隐式取消应用借用。

未解决的隔离目标继续计入活跃数量和字节限额，额度耗尽即背压。无法安全关闭时，析构保留未结清账本；宿主也必须保留 Slab、backing、context、provider 和 MemoryBudget。这里没有自动撤权、无限重试、WR 重放或隐式 TCP 切换。

## 验证范围

Mock 测试覆盖乱序准入、同 SN 冲突、窗口推进、全身份匹配、准入回滚、发布后隔离、可信终结、迟到 DONE、应用持有与共享 Slab 独立额度，并检查预分配后的数据路径无分配。完整回归结果记录在 [roadmap](roadmap.md)。UB 真机和 WRITE 通知的端到端实现回归尚未执行。
